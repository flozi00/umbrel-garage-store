# RustFS on Umbrel

Install **RustFS** from this community app store. It starts an S3-compatible
object storage server and the built-in management console.

| Purpose | Address / credential |
| --- | --- |
| Web console | Open the RustFS app tile (Umbrel port `3903`) |
| S3 API (LAN, HTTP) | `http://umbrel.local:3902` |
| Root access key / Console username | `UMBRELRUSTFS` |
| Root secret key / Console password | The password displayed on this app's Umbrel page |
| AWS SDK region | `us-east-1` (unless your client specifies another region) |

The root secret key is generated by Umbrel (`APP_PASSWORD`) rather than being
hard-coded into this repository. Treat it as an administrator credential; for
applications, create dedicated users or service accounts with limited access.

To test from a machine with the AWS CLI, substitute the password shown by Umbrel:

```bash
AWS_ACCESS_KEY_ID=UMBRELRUSTFS \
AWS_SECRET_ACCESS_KEY='<Umbrel app password>' \
AWS_DEFAULT_REGION=us-east-1 \
aws --endpoint-url http://umbrel.local:3902 s3 ls
```

Check service health without credentials:

```bash
curl -fsS http://umbrel.local:3902/health
```

## Data and networking

Object data is kept under `~/umbrel/app-data/florian-rustfs/data/`, not inside
the container, so app/container updates do not remove it. The `hooks/pre-start`
script sets the storage directory owner to UID/GID `10001:10001` as required
by the official rootless RustFS image. When importing a backup with different
file ownership, restore those permissions recursively **while the app is
stopped** before restarting RustFS.

Port `3902` exposes the S3 API over **plain HTTP** on the host network. Do not
forward it directly to the public internet. Use HTTPS termination and access
controls for remote clients. RustFS's single-node, single-disk deployment does
**not** provide erasure coding or replication; make regular backups of the
data directory with the app stopped or using a consistent filesystem snapshot.

The RustFS Console is not mapped to another host port: Umbrel's app proxy routes
the app tile to the container's port `9001`, while the S3 API inside the
container listens on `9000`.

Upstream documentation: https://docs.rustfs.com/en/installation/container/docker
